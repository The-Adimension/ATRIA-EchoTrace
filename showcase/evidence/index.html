2 · Do the two metrics agree?

The main page argues that point-to-curve distance is the right metric for a coordinate model. It would be convenient if Dice also disagreed with it — that would make the re-scoring look decisive. It does not, and the honest version is more useful.

They mostly agree, and that is worth saying plainly. So re-scoring with point-to-curve did not overturn the ranking — a frame Dice calls bad is usually a frame the distance metric calls bad too.

The case for point-to-curve was never that Dice disagrees. It is that Dice measures a rasterisation the model never performed: the adapter emits coordinates, and converting them to a filled region inserts a step that is ours, not the model's. Point-to-curve asks the question the output can actually answer — did the points land on the tracing? Changing it changed the interpretation, not the model. The agreement above is evidence that both were measuring something real; the choice between them is about which object is being measured.

3 · What the coordinate contract costs downstream

The adapter emits parseable coordinates. It does not emit volumes or ejection fraction, and it was never trained to. But coordinates are the substrate those quantities are built from, so it is fair to ask whether the representation itself loses anything on the way up the clinical stack. It does not, and the control below is how we know.

The control. Take the expert 30-point polygons — not the model's — push them through the identical biplane Simpson implementation CAMUS ships, and compare against the clinically reported EF in each patient's Info_4CH.cfg. That isolates what the representation and the derivation cost, with the model removed from the picture.
The 30-point representation is essentially lossless through the clinical chain. Expert polygons reproduce the reported EF with a bias of −0.10 points and a median absolute error of 0.0 — limits of agreement −1.8 to +1.6. Resampling an expert tracing to thirty coordinates and rebuilding a ventricular volume from it costs nothing measurable. That is a result about the contract this whole platform is built on, and it is the strongest one on this page.

Where the gap actually is — and why the primary metric cannot see it

With the derivation cleared, the remaining error is the contours. It is not spread evenly:

Model vs expert, same derivationEnd-diastole End-systole
Enclosed area, relative error+7.9% +28.0%
Volume, relative errorEDV +14.0% ESV +49.9%
Median point-to-curve4.74 mm 5.49 mm

The model over-encloses — by +17.9% on average, and far more at end-systole, when the chamber is smallest. Since EF = (EDV−ESV)/EDV, inflating ESV by 35.9 percentage points more than EDV drives EF down; that is the whole bias.

Point-to-curve is a localisation metric, and it is blind to this. End-systole is only 16% worse in millimetres (5.49 vs 4.74) but 3.5× worse in enclosed area (+28.0% vs +7.9%). A contour sitting uniformly outside the true border scores well on distance while systematically inflating area — and the same absolute offset costs proportionally far more on a small chamber. No single metric is sufficient; distance and area measure different failures of the same contour.
Read this as a roadmap item, not a verdict. Neither shipped adapter is converged — both were stopped while training and evaluation loss were still falling, to fix a reference point rather than chase a number. What this analysis provides is a specific, quantified target for the training that continues: end-systolic over-enclosure, measured in area rather than millimetres. That is more useful than a better headline figure.
